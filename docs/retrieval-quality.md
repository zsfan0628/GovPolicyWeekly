# 采集质量与复核（本地开发版）

## 入口从哪里来

先访问并抽查官网、列表、页面控件及公开列表接口，再维护 `config/sources.yaml` 的站点、地址和栏目名称。
历史检查过程见[2026-10-18 审查记录](site-audit-2026-10-18.md)。这不是对网站全部内容的逐篇人工验收。
`config/crawl_scope.yaml` 选取日常栏目。运行时仍会识别允许的子栏目、下一页和文章，而不是硬编码每篇文章。
新发现的同站、同名但不在允许分支的栏目记入 `column_review.json`，供人工核实，不会自行扩大采集范围。

## 怎样读结果

| 文件或操作 | 含义 |
|---|---|
| `coverage_summary.json` | 每个列表入口的结果、提取链接数、候选数、停翻或继续翻页的原因。识别到目录不等于读到正文；只看到菜单、占位页或栏目跳回首页不当作正常零结果。 |
| `attachment_candidates.json` | 作为候选入口跳过的文档地址、列表标题、栏目和已知日期。不是本周确认收录的条目，也不是下载结果。 |
| `historical_date_hints.json` | 取得正文但所有已识别日期线索都在本期之前，且没有可靠发布日期的页面。不是已确认过期；保留地址、栏目和原因，覆盖仍标为部分完成，不与 HTTP 失败混排。 |
| `attachment_downloads.json` | 开启附件下载时，在 PDF 导出之后单独保存下载结果；失败不会变成网页不存在。 |
| `runtime_summary.json` | 当前尝试耗时、候选状态、去重前收录和最终条目数；模型候选、缓存、实际生成 HTTP 请求、失败与暂缓分别统计。请求次数不等于服务商计费次数。 |
| `attempts/<id>/` | 每次尝试有开始记录；正常结束后保存本次日志、统计和状态变化。恢复前保留已有的日志和摘要，包括旧版任务当时保存下来的部分。 |
| 继续／补采失败项 | 使用原任务的范围和检查点，复用完成项。 |
| 仅重试模型 | 使用已保存正文和当前模型设置；不会重抓网站。明确 401 会暂停本次任务后续未缓存复判，已在途请求可能仍返回。403、超时不会被当作同一类暂停条件。 |
| 重新核验所选站点 | 按工作台当前范围新建任务，不覆盖旧报告；不复用正文或模型缓存，进一步核对发现的候选日期。不是全站无限翻页。 |

## 人工标注样本

对同一报告周期，从官网独立选取样本，同时抽查程序收录和排除的页面。
样本 JSON 为数组，每条填写 `url` 和 `decision`：必须收录用 `include`，应排除用 `exclude`，有争议用 `discuss`。
运行 `python -m scripts.check_review_sample data.json labels.json`，结果按地址列出样本内漏收、误收和待讨论项。
未标注的报告条目不自动算错；没有人工金标准时，不提供查全率结论。

## 仍需人工判断

标题下的“日期＋来源”优先于 CMS 元数据。可靠列表日期与明确正文日期跨越区间边界时，两个方向都核查。启用模型后，只在有有效正文、存在本期日期且有可引用的发布日期语境时，发送标题和有限的日期原文片段（不传整页）做日期复核。模型只能选择已有证据，角色和原文均经程序核对；由程序判断是否在期内。

日期复核默认不限次数。要控制请求量，在“模型复判”中勾选“限制日期复核请求”，或使用 `--date-review-budget N`。所有站点共用上限，每次发送日期请求前预留一次，重试或切换接口也计数；缓存命中不计数。设为 0 仅使用已有日期复核缓存，不影响内容分类请求，也不限制网页抓取。恢复同一任务沿用原上限和已用次数；要更改上限请新建任务。

达到上限、证据不足或关闭模型均保留待核查。接口失败可仅重试模型；缓存与内容分类分开。已收录的模型日期在 JSON 和 Excel 中记录引文与模型，PDF 的“条目判定依据”记录引文。升级后的新规则不会自动更正旧报告，建议新建任务重新核验。

不能断言未知栏目全部发现、无法访问页面没有政策、附件正文已经解析、或政策变动已比对旧版。
弱日期、正文只有标题／占位提示会标为待核查。正文指向附件时保留链接；不自动 OCR 任免名单。
正式文件收录口径不变，行业相关性与任免阶段单独标记，不能仅凭标题认定法律生效日期。
同名异文不再仅凭标题删除；不同单位同题且全文哈希一致时提示其他发布单位，保留各自记录，不猜测谁是权威原发。
