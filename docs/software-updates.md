# 程序与站点配置更新

这是本地新版的功能。已发出的安装包不会因为仓库的源码发生变化就立即获得更新能力。
首次使用需要手动换到带更新功能的版本，此后安装版和便携版都可以在应用内升级。

## 用户如何操作

- 正常启动桌面工作台时在后台检查一次。工作台右上角只在有更新时显示下载箭头。
  “设置”和“站点管理”也有手动检查入口。离线不会阻塞采集，网络恢复后可重试。
- 检查只是向项目的公开 GitHub 地址读取版本清单，不会发送报告、模型接口或 API Key。
  点箭头可查看更新类型和大小；点“下载”才取包，校验后还需点“应用站点配置”或“安装并重启”。
- 站点包只有数据。应用后列表、地区数量和地图刷新；旧站保留勾选，新站默认未勾选。
  新地区有代表点才显示地图标记，没有坐标仍可在列表和搜索中找到。新任务使用新配置，
  从断点恢复的任务继续使用原快照。不会自动发现或收录未经维护者确认的新栏目。
- 程序更新不是增量补丁。安装版下载完整安装器，安装到原目录；便携版下载完整 ZIP，
  关闭后替换程序文件和 `_internal`，不会删除整个便携目录。目录不可写时可选择另一个
  父目录，在其下创建新的 `GovPolicyWeekly`；此时原目录仍在，不会搬走旧目录内的自定义文件。
- 采集或模型请求尚未结束时不能应用更新。设置与历史报告不是更新内容；自定义报告目录
  不要放在软件的 `_internal` 中。程序替换后先离线自检，通过才启动新软件。
  失败时助手尝试恢复原程序文件；错误记录在更新下载目录的 `update-error.txt`。

## 只发布站点、栏目或地图

1. 修改 `config/sources.yaml`、`config/crawl_scope.yaml` 或 `config/map-regions.yaml`。
   地图使用地区代表点，经纬度为度，`lx` / `ly` 是标注框在图上的相对位置。
   需要新的解析逻辑、登录流程或地图绘制能力时仍要发程序版本。
2. 将 `config/site-revision.txt` 中的整数加一，运行
   `python -m scripts.prepare_site_update --notes "本次更新说明"`。
   它只在本地生成 `updates/catalogue.json` 和 `updates/sites.json`。
3. 检查配置和测试结果。获准发布时，把源配置和上述两个文件放入同一个主分支提交；
   **不需要发布程序 Release**。老程序不支持的新数据格式应升级协议，不要静默复用版本号。

## 发布程序

Windows 发布脚本将版本号和构建号写入程序，并为两个渠道分别添加标记。
Release 需要包含安装器、便携 ZIP 以及 `program-update.json`，三者必须来自同一次构建。
客户端只接受匹配稳定 Release 的资产、大小和 SHA-256；版本号相同但构建号更大也可提示。
macOS 源码工作台可以更新站点，但不会尝试安装 Windows 软件。

更新信任来源是固定的官方仓库和 HTTPS；SHA-256 校验完整性，不是独立的代码签名。
网络失败、缺少校验摘要或校验不匹配时不会安装。下载页旧版不带清单时不会误报新版。
